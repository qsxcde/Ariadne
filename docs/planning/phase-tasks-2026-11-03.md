# 各阶段任务清单（2026-11-03）

> 来源：[阶段目标与门禁](goals-2026-11-03.md)、[功能点清单](feature-backlog-2026-11-02.md)、[M0 设计稿](m0-paper-model-2026-11-02.md)、[界面清单](ui-screens-2026-11-02.md)、[RAG 策略](../analysis/rag-strategy-2026-11-02.md)
> 使用方式：只展开当前阶段；任务系统保留阶段级任务，本清单用于阶段内逐项勾选。进入某阶段时，再把该阶段子任务提升为 TaskCreate，避免一次性塞入几十个任务。
> 完成定义：代码、测试、契约、UI 三态、数据迁移/回滚、日志、文档、成本预算、鉴权，缺一不算完成。

## 0. 任务规则

- 一个任务对应一个可验证改动，不按文件拆。
- 每个任务必须有依赖和验收证据；没有证据的任务不算完成。
- 状态只用：未开始 / 进行中 / 已达成 / 未达成 / 暂缓。
- 阶段出口检查全部通过，才允许进入下一阶段。

## 8. 使用建议

1. 阶段开始时，把该阶段的任务表复制到 TaskCreate，按依赖串 blockedBy；不要一次性创建全部阶段。
2. 每周复盘只更新本阶段任务状态，不跨阶段比较进度。
3. 阶段出口检查全部通过后，再展开下一阶段任务表。
4. 任何新增功能先判断属于哪个阶段；不属于当前阶段的，写入 backlog，不插队。
5. 任务状态与目标卡 KR 状态保持一致；目标卡不达标，任务不能标完成。
