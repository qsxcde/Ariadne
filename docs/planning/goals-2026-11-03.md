# 阶段目标与验收门禁（2026-11-03）

> 问题：如何按阶段完成全部功能点？
> 核心答案：**不要用「完成 49 个功能点」当目标。** 每个阶段只设一个用户结果目标 + 3–6 个关键结果 + 明确的退出条件；功能点是达成目标的手段，不是目标本身。
> 关联：[产品规划](product-plan-2026-11-02.md)、[功能点清单](feature-backlog-2026-11-02.md)、[M0 设计稿](m0-paper-model-2026-11-02.md)、[界面清单](ui-screens-2026-11-02.md)、[RAG 策略](../analysis/rag-strategy-2026-11-02.md)
> 执行状态（2026-11-03）：M0 已完成并提交；M1 自动化代码（历史注入/检索 scope/chunk 引用/brief/explain/Today）已落地，真实模型评测阻塞于无效 DEEPSEEK_API_KEY。

## 0. 目标设定原则

1. **Outcome > Output**：目标写「用户能完成什么」，不写「做完哪些功能」。
2. **一阶段一主目标**：每个阶段只有一个 Objective，避免并行铺开。
3. **3–6 个关键结果**：每个 KR 必须可验证（有命令、有数据、有演示路径）。
4. **先过门禁，再进下一阶段**：上一阶段的核心 KR 不达标，不启动下一阶段。
5. **Must / Should / Won't**：每阶段明确范围上限，防止功能蔓延。
6. **功能级 DoD 统一**：代码、测试、契约、UI 状态、文档、可观测性一起验收。
7. **初始阈值可校准**：没有基线的百分比先标「待基线校准」，阶段开始后用真实数据定值。
8. **有停止规则**：某些功能如果验证不成立，允许砍掉，而不是硬做完。

## 1. 北极星与护栏指标

**北极星指标**：每周「读完并留下笔记」的论文数。它同时衡量阅读、理解和沉淀，不容易被功能数量刷上去。

| 类型 | 指标 | 用途 |
|---|---|---|
| 北极星 | 每周读完并留下笔记的论文数 | 判断产品是否真的有用 |
| 激活 | 导入 → 打开 → 首条笔记的转化率 | 判断上手是否顺畅 |
| 信任 | 引用精确率、无依据回答率 | 判断能不能信 |
| 效率 | 从导入到首份速读卡的时间、每篇笔记数 | 判断是否省时间 |
| 进度 | 队列平均停留天数、周目标达成率 | 判断是否形成习惯 |
| 跟进 | Feed 保存率、新论文→阅读转化 | 判断跟进功能是否值得做 |
| 成本 | 每篇速读卡 token 成本、每次问答成本 | 判断是否可持续 |
| 稳定性 | 任务失败率、迁移失败次数、P0 数 | 判断能不能交付 |

## 2. 阶段目标卡

### M0 · 让进度可记录

**Objective**：把论文从「会话附件」变成可管理的资产，阅读状态、位置和笔记在刷新后不丢。

**用户结果**：研究生可以导入 10 篇论文，按状态整理，打开一篇读到一半，做高亮和笔记，关闭再打开能继续读。

**关键结果**：

| KR | 目标值 | 证据 |
|---|---|---|
| KR1 数据迁移零丢失 | v7 真实副本迁移到 v8；documents/chunks/messages/index 关联完整；foreign_key_check 为空 | 迁移测试 + 迁移日志 + 备份恢复演练 |
| KR2 资产闭环 | 导入 10 篇 PDF；同 hash/DOI/arXiv 不重复建论文；按状态/集合/标签筛选可用 | 手工验收 + 去重测试 |
| KR3 阅读闭环 | 5 篇论文完成「打开 → 标记在读 → 高亮 → 笔记 → 关闭 → 重开续读」；状态/进度/笔记 100% 恢复 | 端到端演示 |
| KR4 质量门禁 | 141 个后端用例全绿；ruff/mypy 通过；前端 test/lint/typecheck/build 通过；契约 diff 为 0 | CI 或本地命令输出 |
| KR5 可用性 | 100 篇论文的文献库首屏 < 1s；无手工改库；0 个 P0 | 本地测速 + 走查 |

**范围**：D1–D9、L1/L2/L5/L6/L7、R1/R7、P1/P2、T1 基础。

**明确不做**：任何 AI 生成、collection 级检索、Feed、团队协作。

**退出条件**：用真实 v7 副本完成迁移；导入 10 篇论文并走通阅读闭环；回滚步骤写入文档。

**停止规则**：出现任何数据丢失或迁移失败，停止 M1，先修数据层。

### M1 · 让单篇读得懂

**Objective**：读一篇论文时，能在 10 分钟内得到可信速读卡，追问不脱节，引用能回到原文。

**用户结果**：研究生导入一篇论文，先看速读卡判断是否值得精读；精读时划词解释/翻译、看章节摘要、追问；每条结论都能点回原文。

**关键结果**：

| KR | 目标值 | 证据 |
|---|---|---|
| KR1 速读卡 | 3 篇论文生成 TL;DR/贡献/方法/实验/局限/结论；所有结论带 provenance；无依据时拒答 | 3 篇端到端演示 + 人工核对 |
| KR2 引用可信 | 50 题标注集上 citation precision ≥ 0.9；引用 100% 可回跳到页/chunk | 评测报告 + 点击走查 |
| KR3 多轮不脱节 | 20 个指代/追问脚本通过率 ≥ 90% | 多轮回归脚本 |
| KR4 阅读效率 | 划词解释/翻译、章节摘要、笔记保存都在阅读器内完成；80% 操作不跳页 | 走查记录 |
| KR5 进度联动 | Today 显示继续阅读/队列/周目标；状态与进度更新 ≤ 2s | 手工验收 |
| KR6 成本与延迟 | 首 token p95 ≤ 5s；每篇速读卡 token 成本 ≤ 配置预算；重复生成命中缓存 | 日志/usage 统计 |

**范围**：L3/L8、R2/R3/R4/R8/R12、P4、T2/T3。

**退出条件**：3 篇论文从导入到笔记无跳页；citation precision 达标；多轮脚本通过。

**停止规则**：citation precision < 0.8 或多轮通过率 < 80%，不启动 M2，先修 prompt、历史注入和引用校验。

### M2 · 让课题管得住

**Objective**：管理一个 5–20 篇论文的课题，能跨论文问答、做对比、生成周报并导出。

**用户结果**：研究生为一个课题建集合，问「这几篇的方法差异」，得到带 paper 标识的回答；生成方法/数据集/指标对比表；周末看自动周报。

**关键结果**：

| KR | 目标值 | 证据 |
|---|---|---|
| KR1 集合可用 | 10 篇论文、2 个集合；collection 检索/过滤可用 | 手工验收 |
| KR2 跨论文问答 | 30 题跨 2+ 论文；答案准确率 ≥ 0.8；每条引用带 paper_id + chunk | 标注集评测 |
| KR3 对比表 | 2–5 篇 × 方法/数据集/指标/局限；字段完整率 ≥ 90%，准确率 ≥ 0.8；可导出 | 评测 + 导出样例 |
| KR4 周报 | 自动汇总读完/笔记/开放问题/下周队列；可编辑 | 周报样例 |
| KR5 进度可见 | Dashboard 显示在读/待读/已完成/积压 | 走查 |
| KR6 质量门禁 | 摘要忠实度、对比准确率评测达标；无回归 | 评测报告 |

**范围**：L4、R5/R6/R9（集合）/R10、P3/P5/P6/P7/P8、S1/S4、T4/T5/T6。

**退出条件**：10 篇论文的课题能产出对比表 + 周报，不需要手工复制粘贴。

**停止规则**：对比准确率 < 0.7，或 collection 问答使用率极低，暂缓 M3，先简化综合页。

### M3 · 让领域跟得上（可选）

**Objective**：每周用 10 分钟跟进领域新论文，不漏读、不重复读。

**用户结果**：研究生订阅 3 个关键词/作者/venue，每周看到一批新论文；每条有推荐理由；一键存入队列并进入阅读。

**关键结果**：

| KR | 目标值 | 证据 |
|---|---|---|
| KR1 订阅可用 | 3 个订阅；新论文抓取成功；失败可重试 | 手工验收 |
| KR2 去重 | 重复推荐率 < 5%；已读/已存/已忽略不再出现 | 去重测试 |
| KR3 可解释 | 每条推荐都有「为什么推给我」 | 走查 |
| KR4 转化 | 连续两周，每周至少 1 篇从 Feed → 队列 → 阅读 | 事件统计 |
| KR5 可控 | 可静音/忽略/限制数量；不形成第二个收件箱 | 走查 |

**范围**：F1–F5、S2。

**退出条件**：连续两周达到「Feed → 阅读」转化，且没有重复推荐投诉。

**停止规则**：连续两周保存率 < 10%，砍掉 Feed 或缩窄为作者/venue 提醒。

### M4 · 让知识沉淀下来

**Objective**：阅读产出可复用，关键更新不漏。

**用户结果**：研究生把笔记导出到 Markdown/Obsidian，把综述矩阵导出 CSV；关注的论文有新版本/新引用时收到提醒。

**关键结果**：

| KR | 目标值 | 证据 |
|---|---|---|
| KR1 导出 | 笔记/批注 → Markdown；对比矩阵 → CSV/Markdown；成功率 100% | 导出样例 |
| KR2 同步 | Zotero/Notion 单向同步可用；冲突有提示；幂等 | 集成测试 |
| KR3 提醒 | 新论文/新版本/新引用可配置；Digest 可查看；不重复提醒 | 走查 |
| KR4 引用关系 | 对 DOI/arXiv 论文可查「谁引用/引用了谁」；覆盖率 ≥ 80% | 元数据查询 |

**范围**：F6–F9、R11、S3、L9。

**退出条件**：能导出笔记并查到一次引用更新，不需要手工搜索。

**停止规则**：导出使用率低则保留导出、砍掉同步；引用图数据覆盖不足则只做「相关论文」不做图。

## 3. 每个功能点的 DoD

不管属于哪个阶段，一个功能点只有满足以下条件才算「完成」：

| 维度 | 要求 |
|---|---|
| 代码 | 类型标注完整；ruff/mypy 通过；不新增模块级全局 settings |
| 测试 | 至少 1 个单元或集成用例；关键路径有端到端或手工脚本 |
| 契约 | OpenAPI 重新生成；contracts/ diff 为 0；前端类型同步 |
| UI | loading / empty / error 三态；PC 1280 可用；不新增移动端页面 |
| 数据 | 涉及持久化的，必须有迁移/回滚或幂等保证 |
| 可观测性 | 日志带 paper_id / job_id；关键动作有事件或计数 |
| 文档 | 事实变化写 wiki；决策/计划写 planning |
| 成本 | 涉及 LLM 的，说明 token/延迟预算与缓存策略 |
| 安全 | 鉴权/归属校验；文件路径不越界 |

## 6. 每周复盘模板

每周只回答四个问题：

1. 本周用户能多做哪一件以前做不到的事？
2. 哪个 KR 有可验证的进展？证据是什么？
3. 当前最大阻塞是什么？需要砍掉什么？
4. 下周只做哪 3 件事？

不要用「本周写了多少代码/多少功能点」当进展。

## 8. 一句话

**目标不是「完成所有功能点」，而是每个阶段结束时，用户能完成一条以前做不到的完整任务。** 功能点是这条任务的零件；门禁通过，才允许进入下一阶段。
