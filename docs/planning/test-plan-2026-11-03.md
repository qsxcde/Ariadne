## 0. 中间件策略

- **M0 / M1 不引入外部中间件**：SQLite 与 FAISS 都是嵌入式，测试不需要 Docker 服务。
- 后续如果引入 Redis、PostgreSQL、消息队列或独立向量服务，**统一通过 docker compose 启动**；本地、CI、测试使用同一镜像与版本。
- 测试计划必须包含中间件健康检查与清理步骤；禁止使用未版本化的本地服务。
- 已提供 **docker-compose.test.yml**：启动一个 OpenAI 兼容的 mock LLM/Embedding 服务（docker/mock-llm），用于验证完整 HTTP 链路；运行 scripts/run_mock_llm_tests.sh。
- 该 mock 服务是**确定性测试中间件**，不是真实模型评测；真实 DeepSeek 评测仍作为发布门禁。

## 3. 基线如何决定下一阶段

1. 阶段结束先跑通用门禁，再跑该阶段专项测试。
2. 把结果写入目标卡的 KR 表，状态标记「已达成 / 未达成」。
3. 只有全部 KR 达成，才把下一阶段任务提升为 TaskCreate。
4. 未达成时只做修复，不并行开下一阶段；必要时缩小范围或触发停止规则。
5. 任何数据丢失、迁移失败、鉴权绕过都视为 P0，直接停止后续阶段。
