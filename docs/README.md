# Ariadne 文档

文档按用途分三层，避免把「事实基线」和「时点分析 / 规划」混在一起。

| 目录 | 用途 | 入口 |
|---|---|---|
| [wiki](wiki/README.md) | **工程事实基线**：系统如何工作、数据模型、API、配置、开发与排障 | 所有人 |
| [analysis](analysis/README.md) | **时点分析**：审计、现状复核、能力缺口、RAG 策略判断 | 负责人 / 开发 |
| [planning](planning/README.md) | **规划与设计**：产品规划、M0 设计、功能清单、界面清单、整改计划 | 负责人 / 产品 / 开发 |

## 文档约定

- **wiki 只写当前代码如何工作。** 代码变更后同步更新，不把计划、审计、路线图放进去。
- **analysis 是时点快照。** 结论要标注日期与代码基线；后续变化时新增文档或更新状态，不改写历史结论。
- **planning 写下一步要做什么。** 它可以引用 analysis 和 wiki，但不作为事实来源。
- 新增文档先判断类型：事实进 wiki，分析进 analysis，计划进 planning。
